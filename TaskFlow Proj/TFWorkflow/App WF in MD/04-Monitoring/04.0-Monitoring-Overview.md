## 1. Module Overview
Monitoring is where TaskFlow's tasks are kept. Users list, create, open, edit, move, reassign and delete tasks. They talk about a task in its discussion and can see everything that happened to it in its activity history. The Kanban board shows the same tasks as status columns, and the Employee Workload screen shows how much work each employee has.

## 2. Purpose / Business Value
- Gives every task one owner, one deadline and one status, and every change is recorded with who made it and when.
- Each person sees only the tasks they are allowed to see: Employees see their own tasks, Managers see their team's tasks, Administrators see all tasks.
- Managers can spot overdue and unbalanced work (board highlights, workload counts, the "High load" badge) and move tasks to someone else, giving a reason that is recorded.
- People are told about changes as they happen. Assignment, reassignment, comments and worked-hours changes send in-app notifications, and most of them also send internal mail.
- Worked hours are tracked against the estimate, so managers can see how much effort a task has left.

## 3. Who Can Access This Module

| Role          | Can See Module | Can Use Module | Access Level (Own / Team / Organization) |
|---------------|:--------------:|:--------------:|------------------------------------------|
| Administrator | ✅ | ✅ | Organization (holds `tasks.view.all` and the organization dashboard, so sees every task) |
| Manager       | ✅ | ✅ | Team (holds `tasks.view.all`, but because the role has the team dashboard and not the organization dashboard, the system limits it to the team's tasks plus the tasks the manager created, is assigned or is notified about) |
| Employee      | ✅ | ✅ | Own (tasks they are assigned, created or are notified about) |
| Custom Role   | Configurable | Configurable | As granted (Own by default; Organization or Team when `tasks.view.all` is granted) |

Users with `tasks.view.all` see the menu **TaskFlow Monitoring → Task Management / Employee Workload / Board**. Everyone else sees **Task Management → My Tasks / Board**. Employee Workload is shown only to users with `workload.view`, and Board only to users with `board.view`.

| `tasks.comment.edit` | Edit own task comments | Granted | Granted | Granted | Configurable |
| `tasks.comment.delete` | Delete own task comments | Granted | Granted | Granted | Configurable |
| `tasks.activity.view` | View task history | Granted | Granted | Granted | Configurable |

Which child uses which key: 04.1 uses the `tasks.view.*`, `tasks.create`, `tasks.update`, `tasks.delete`, `tasks.reassign`, `tasks.recipients.manage` and `tasks.status.change` keys; 04.2 uses `tasks.comment.*` and `tasks.activity.view`; 04.3 uses `board.*` and `tasks.status.change`; 04.4 uses `workload.*`.

## 7. Related Modules
- **Dashboard** – Dashboard chart segments open the Task List as a drill-down. The Manager or Administrator dashboard keys also decide whether a role with `tasks.view.all` is limited to its team.
- **Management** – Projects (required on every task), employees (assignee, recipients) and departments or project-manager flags (which define a Manager's team) come from Management.
- **Communication** – Assignment, reassignment, comments and worked-hours changes create in-app notifications and internal mail. Deadline reminders use each task's reminder fields.
- **Settings** – Reminder Settings give the default reminder intervals. Application Settings give the default priority, the time zone used for "Due today" and "Overdue", and the switches for in-app notifications and mail. Role Configuration grants the Monitoring keys.
- **Reports** – Reports use the same task data. Managers move between Workload and Reports for planning.
- **TaskFlow Assistant (TFA)** – The assistant reads the user's tasks (for example "get my tasks" and "prioritise tasks") through the same task scope.

## 8. Expected Outcome
Every user sees exactly the tasks they are allowed to see. Managers and Administrators create, edit, reassign and (Administrators) delete tasks, and everyone moves their tasks through the allowed statuses on the details screen or the board. The people on a task discuss it in one place and are told about each change, and the activity history shows what changed, who changed it and when. Managers can see workload imbalances and overdue work and move tasks to balance it.
