## 1. Module Overview
The Settings module is where authorized users change how TaskFlow behaves for the whole organization, without editing source code. It has four screens under the **Settings** menu. **Application Settings** holds the brand name, timezone, default task priority and in-app notifications. **Reminder Settings** controls the automatic deadline reminders. **Role Configuration** manages roles and their permissions. **TFA Settings** chooses the AI model and server used by TFA, the TaskFlow Assistant.

## 2. Purpose / Business Value
- Settings such as reminder intervals, timezone and default priority are changed from the screen, not in code (BRD Screen 13 FR-4, Screen 20 FR-1).
- The whole application uses one timezone to decide which calendar day a deadline falls on, so "due today" and "overdue" mean the same thing for everyone (BRD business rule 17).
- Access is controlled by permissions. An organization can create its own **custom roles**, so a role gets the screens and actions it needs and nothing more.
- The organization chooses which AI provider TFA uses: a free local server (Ollama) or a cloud service (Google Gemini, OpenAI GPT). API keys are stored encrypted and are never shown again.
- Sensitive configuration stays private. API keys are never sent back to the browser, and the settings that every user can read contain nothing secret (BRD Screen 20 FR-5).

## 3. Who Can Access This Module

| Role          | Can See Module | Can Use Module | Access Level (Own / Team / Organization) |
|---------------|:--------------:|:--------------:|------------------------------------------|
| Administrator | ✅ | ✅ | Organization (all four screens) |
| Manager       | ✅ | ✅ | Organization (Reminder Settings only, by default) |
| Employee      | ❌ | ❌ | – (no Settings screen by default) |
| Custom Role   | Configurable | Configurable | Organization, for each screen whose permission is granted |

> Note: Every setting on these screens applies to the **whole organization**. There is no "own" or "team" version of a setting.
> Note: Any signed-in user can **read** the application settings (the brand name in the header and the default priority on Create Task), but only holders of `settings.application.manage` can change them.

## 4. Screens in This Module

| # | Screen Name | Menu Path | Purpose | Visible To |
|---|-------------|-----------|---------|------------|
| 1 | Application Settings | Settings → Application Settings | Brand name, default timezone, default task priority, in-app notifications on/off | Administrator; custom roles with `settings.application.manage` |
| 2 | Reminder Settings | Settings → Reminder Settings | Turn deadline reminders on/off, default reminder days, overdue frequency, delivery to Mail | Administrator, Manager; custom roles with `settings.reminders.manage` |
| 3 | Role Configuration | Settings → Role Configuration | View roles, and create, edit, copy and delete custom roles and their permissions | Administrator; custom roles with `roles.manage` |
| 4 | TFA Settings | Settings → TFA Settings | Choose the AI model and server TFA uses, add/remove models, enter API keys, test the connection | Administrator; custom roles with `settings.ai.view` |

The **Settings** menu group only appears when the user holds at least one of the four screen permissions. If a user opens a Settings address without the permission, they are sent back to their dashboard.

## 6. Permission Summary (Module Level)

| Permission Key | Description | Administrator | Manager | Employee | Custom Role |
|----------------|-------------|:-------------:|:-------:|:--------:|:-----------:|
| `settings.application.manage` | Change application-wide settings | Granted | Denied | Denied | Configurable |
| `settings.reminders.manage` | View and change deadline reminder settings | Granted | Granted | Denied | Configurable |
| `settings.ai.view` | See which AI providers and models are configured | Granted | Denied | Denied | Configurable |
| `settings.ai.edit` | Configure AI providers, keys and models (needs `settings.ai.view`) | Granted | Denied | Denied | Configurable |
| `settings.ai.test` | Run a connection test against a provider (needs `settings.ai.view`) | Granted | Denied | Denied | Configurable |
| `settings.ai.model.remove` | Remove a configured model from a provider (needs `settings.ai.view`) | Granted | Denied | Denied | Configurable |
| `roles.manage` | Open Role Configuration and create, edit and delete custom roles | Granted | Denied | Denied | Configurable |
| `roles.view.all` | See all roles (otherwise only one's own) | Granted | Denied | Denied | Configurable |
| `roles.modify.access` | Add or update permissions (otherwise view mode) | Granted | Denied | Denied | Configurable |
| `roles.administrator.assign` | Make an account an Administrator, or take the role away | Granted | Denied | Denied | Denied |
| – (signed in) | Read application settings (brand name, default priority) | Always On | Always On | Always On | Always On |

> Manager and Employee values are the defaults given when the permission is first created. The Manager and Employee roles are system roles and cannot be changed on the Role Configuration screen.
> The Administrator role is given every permission again each time the application starts. `roles.administrator.assign` can only be held by the Administrator role, so for a custom role it is shown as Denied.

Each child document repeats the rows for its own keys.

## 7. Related Modules
- **Monitoring (Task Management)** – Create Task pre-selects the default priority from Application Settings and the default reminder days from Reminder Settings.
- **Communication (Notifications, Mail)** – The reminder engine reads Reminder Settings (on/off, deadline-day reminder, Mail delivery). The in-app notifications switch in Application Settings decides whether bell notifications are created at all.
- **Management (Employee Management)** – Users are given roles there. A custom role must be emptied there before it can be deleted. Giving the Administrator role needs `roles.administrator.assign`.
- **TaskFlow Assistant (TFA)** – Uses the model and server saved in TFA Settings. Only configured providers are offered in the TFA window.
- **Dashboard and Reports** – Use the application timezone to decide which tasks are due today or overdue.
- **Authentication** – When a custom role's permissions change, its holders are signed out and must sign in again.

## 8. Expected Outcome
An Administrator can maintain the application name, timezone, default priority and notifications from the screen. Managers and Administrators can tune deadline reminders without code changes. The organization can define custom roles that grant exactly the screens and actions each group needs, while the system roles and the permission list stay protected. The Administrator can choose and test the AI model behind TFA and store API keys safely, without exposing them to anyone.
