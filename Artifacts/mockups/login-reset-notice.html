Account

1. The link the administrator copies (Details panel)

Encrypted, lasts 5 minutes and works once. It holds no email and no password, and only the latest reset gives a working link. The administrator generates it when the user is ready and sends it privately.

What the user sees

  1. Opens the link: the address bar shows only the token; the page resolves it and shows the email.
  2. The bell rings with a "1" and stays until the user signs in or updates the password. The page checks every ~2 seconds, so it appears by itself.
  3. Clicking the bell opens the update screen: New password and Confirm password only - the link already proved who the user is On plain /login (no link) the bell does not open this screen: it tells the user to sign in with the password the administrator gave them, and signing in leads to this same New/Confirm screen.
  4. Typing a different Confirm shows "Passwords do not match." straight away.
  5. There is no Cancel or Close. The only action is Update password.
  6. On success the temporary password stops working and the user signs in with the new one.

Safety

never shown The temporary password is not pre-filled or revealed anywhere; the short-lived single-use link is the proof. Sign-in and this update are rate limited, and every refusal is the same generic message.

Limit Before sign-in nothing can stop someone closing the tab. After they sign in, the server still refuses every other page until the password is changed.
