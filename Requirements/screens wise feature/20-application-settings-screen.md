# SCREEN 20: Application Settings Screen

> Source: BRD for Task management.docx · TaskFlow – Intelligent Task Allocation & Tracking System · v1.0 · §2.20

**Screen Name:** System Settings
**Access:** Administrator

## Purpose

Manage basic application-level configuration.

## Screen Elements

- Application name.
- Default timezone.
- Default task reminder intervals.
- Default task priority.
- Notification preferences.
- Save settings button.

## Functional Requirements

1. Allow administrators to configure supported application settings.
2. Apply the configured timezone consistently.
3. Allow default reminder settings to be maintained.
4. Validate settings before saving.
5. Ensure changes do not expose sensitive configuration information.
6. Record significant configuration changes.

## Expected Result

The administrator can maintain basic application settings from the interface. 3. AUTOMATIC DEADLINE NOTIFICATION WORKFLOW This is the main feature of TaskFlow. 3.1 Task Creation When a manager creates a task, the system stores: - Task ID. - Task title. - Assigned employee. - Task creator. - Deadline. - Estimated duration. - Priority. - Task status. - Additional notification recipients. - Reminder configuration. The assigned employee must automatically be included in the notification recipients. The task creator and any selected additional recipients should also receive reminders according to the configured rules. 3.2 Reminder Schedule Default reminder schedule: | Event | Action | |---|---| | Task assigned | Notify the assigned employee | | Two days before deadline | Send reminder | | One day before deadline | Send reminder | | On deadline day | Send due-today reminder | | After deadline | Send overdue reminder once per day | | Task completed | Stop deadline reminders | | Task cancelled | Stop deadline reminders | | Deadline changed | Recalculate future reminders | 3.3 Example Task: Prepare Monthly Report Assigned Employee: Rahul Task Creator: Manager Additional Recipient: Priya Deadline: 15 October, 5:00 PM On 13 October, the system generates a reminder for Rahul, the manager, and Priya. On 14 October, another reminder is generated if the task remains incomplete. On 15 October, the recipients receive a deadline-day reminder if the task is still incomplete. If the task remains incomplete after the deadline, overdue reminders follow the configured schedule. If Rahul completes the task, future deadline reminders stop. 3.4 Notification Channels In-App Notifications The system stores notifications in the database and displays them in the application. Email Notifications The system sends email reminders when SMTP delivery is enabled and correctly configured. If email delivery fails, the system must retain the in-app notification and record the email failure. 3.5 Duplicate Prevention The system must not send the same reminder event repeatedly because the scheduler runs multiple times. Maintain a reminder history that records: - Task ID. - Reminder type. - Scheduled reminder time. - Recipient. - Processing status. - Delivery attempt details. Use appropriate database constraints or transactions to prevent duplicate reminder events. 4. BUSINESS RULES 1. Every task must have a unique task ID. 2. Every task must have an assigned employee. 3. Every task must have a deadline. 4. Estimated duration and deadline must be stored separately. 5. The assigned employee must automatically be included in task notifications. 6. Additional notification recipients can be selected by an authorized manager. 7. Only authorized users can create, modify, reassign, or manage tasks. 8. Employees can update only tasks they are authorized to manage. 9. A task is overdue when its deadline has passed and it is not completed or cancelled. 10. Completed and cancelled tasks must not receive further deadline reminders. 11. Reminder settings must be configurable. 12. Task reassignment must preserve previous task history. 13. Important task changes must be recorded. 14. Users must not be able to access another user's private notifications. 15. The system must prevent duplicate reminder events. 16. Email delivery failure must not prevent in-app notifications from working. 17. The application must use a consistent timezone for deadline comparisons. 18. Deactivated users must not be allowed to log in. 19. Records with dependent data must not be deleted in a way that damages historical information. 20. Dashboard statistics and reports must use consistent calculation rules. 5. NON-FUNCTIONAL REQUIREMENTS 5.1 Performance The application should load ordinary screens and process routine operations without unnecessary delays under the expected office workload. 5.2 Security - Secure password hashing. - Role-based access control. - Server-side input validation. - CSRF protection. - Secure session management. - Protection against unauthorized record access. - Safe database queries. - Secure handling of email credentials. 5.3 Usability The interface should be easy to understand for employees with basic computer knowledge. 5.4 Reliability Task records and notification history must be stored persistently. The scheduler should resume checking deadlines after an application restart. 5.5 Maintainability The application should use a clear project structure and separate authentication, task management, notifications, reports, and database logic. 5.6 Compatibility The application should work in modern desktop browsers and provide a responsive layout for smaller screens. 5.7 Backup Provide a documented method for backing up and restoring the SQLite database. 6. PROJECT SUMMARY TaskFlow – Intelligent Task Allocation & Tracking System is designed to improve office task management by combining employee task assignment, progress tracking, automatic deadline notifications, workload monitoring, and reporting in a single application. Its primary business benefit is to ensure that employees and relevant managers receive timely reminders about assigned work, reducing missed deadlines and improving visibility into office activities. The application should prioritize reliable task management and deadline notifications before adding optional features. This approach keeps the project achievable while demonstrating meaningful full-stack development, database design, authorization, scheduled background processing, and automated testing.
