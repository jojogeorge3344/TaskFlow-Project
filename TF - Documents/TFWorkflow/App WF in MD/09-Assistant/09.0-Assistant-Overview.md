## 1. Module Overview
TFA (TaskFlow Assistant) is the AI assistant built into TaskFlow. It opens as a small panel on the right of every signed-in screen. Users can ask how TaskFlow works, see their upcoming, due-today and overdue tasks, ask what to work on first, and have TFA prepare a mail, a change to their own profile or (for administrators) a change to another user's role. TFA never acts on its own: every prepared action is shown on a card and only happens when the user clicks Confirm.

## 2. Purpose / Business Value
- Gives every user a single place to ask "how do I…?" questions, answered only from TaskFlow's own written help, so users do not need training material or a colleague.
- Turns the task list into a clear, repeatable work order (overdue first, then due today, then nearest deadline and highest priority).
- Saves time on routine work such as writing a mail to "my manager" about a task.
- Keeps the organization safe: TFA can only do what the signed-in user could already do in the application, it refuses passwords and API keys in chat, every action needs the user's confirmation, and every action outcome is recorded in an audit log.
- Lets the organization choose where the AI runs: a local model (Ollama, nothing leaves the machine) or a cloud model (Google Gemini, OpenAI GPT), chosen by an administrator in TFA Settings.

## 3. Who Can Access This Module

| Role          | Can See Module | Can Use Module | Access Level (Own / Team / Organization) |
|---------------|:--------------:|:--------------:|------------------------------------------|
| Administrator | ✅ | ✅ | Own conversation and own actions; task answers follow the user's own task access |
| Manager       | ✅ | ✅ | Own conversation and own actions; task answers follow the user's own task access |
| Employee      | ✅ | ✅ | Own conversation and own actions; task answers follow the user's own task access |
| Custom Role   | Configurable | Configurable | As granted (`assistant.chat`, `assistant.actions.confirm`) |

Notes:
- The TFA button and panel appear only for users who hold `assistant.chat`.
- A user always works with their **own** conversation and their **own** prepared actions. Another user's conversation or action is reported as "not found".
- When TFA lists tasks it uses the same task rules as the Task Management screens, so it never shows a task the user could not open themselves.

## 6. Permission Summary (Module Level)

| Permission Key | Description | Administrator | Manager | Employee | Custom Role |
|----------------|-------------|:-------------:|:-------:|:--------:|:-----------:|
| `assistant.chat` | Chat with the assistant: open TFA, ask questions, choose a model, start new conversations | Granted | Granted | Granted | Configurable |
| `assistant.actions.confirm` | Confirm assistant actions: confirm, edit or cancel actions TFA prepares | Granted | Granted | Granted | Configurable |
| `roles.manage` *(Settings module key, checked by TFA for role changes)* | Prepare and confirm a role change through TFA | Granted | Denied | Denied | Configurable |

Both TFA keys are also given to every role that existed when they were first added. All other TFA features (password help, administrator help, how-to help, task lists) need only `assistant.chat`.

## 7. Related Modules
- **Settings (TFA Settings)** – an administrator configures the AI providers (Ollama, Google Gemini, OpenAI GPT), models and API keys TFA can use. Role Configuration grants `assistant.chat` and `assistant.actions.confirm`.
- **Monitoring (Task Management)** – TFA reads the user's tasks through the same task rules and links to task pages.
- **Communication (Mail)** – mails prepared by TFA are sent as normal TaskFlow internal mail; "find user" uses the mail contact list.
- **Profile** – TFA's profile change uses the My Profile rules; password questions are sent to **My Profile → Change password**.
- **Management (Employee Management)** – TFA's role change uses the employee update; "my manager" uses department managers.
- **Settings (Application Settings)** – the application name and time zone are used in TFA's answers and in deciding what is due today.
- **Legal** – the Privacy and Terms pages describe how assistant conversations and voice input are handled.

## 8. Expected Outcome
Every permitted user can open TFA from any screen, ask how TaskFlow works and get an answer from the official help, see their upcoming and overdue work in a clear priority order, and have routine mails and profile updates prepared for one-click confirmation. Administrators can also change a user's role from the chat. No action ever happens without the user's confirmation, TFA never does more than the user is allowed to do, passwords and keys never pass through the chat, and every action outcome is kept in the audit log.
