## 1. Module Overview
The Dashboard is the first screen a user sees after signing in. It shows a summary of task work at the level the user is allowed to see: the whole organisation for an Administrator, the manager's own team for a Manager, and only the user's own tasks for an Employee. Every chart can be clicked to open the matching tasks in the Task List.

## 2. Purpose / Business Value
- Gives each person one place to see how much work is pending, in progress, completed and overdue, without opening the Task List.
- Lets administrators compare departments, managers, employees and projects, and lets managers spot overloaded team members and delayed work early.
- Lets employees see their own deadlines, progress and project share, while keeping colleagues' workloads private.
- Every figure uses the same rules for "pending", "in progress", "completed" and "overdue", so the dashboards and the Task List always agree.

## 3. Who Can Access This Module

| Role          | Can See Module | Can Use Module | Access Level (Own / Team / Organization) |
|---------------|:--------------:|:--------------:|------------------------------------------|
| Administrator | ✅ | ✅ | Organization (can also open the Manager Dashboard) |
| Manager       | ✅ | ✅ | Team |
| Employee      | ✅ | ✅ | Own |
| Custom Role   | Configurable | Configurable | As granted: Organization if it holds `dashboard.view.organization`, Team if it holds `dashboard.view.team`, otherwise Own |

Every signed-in user has a personal dashboard (`dashboard.view.own` is Always On). The charts and figures also need `dashboard.analytics.view`. The filter bar needs `dashboard.filters.use`.

## 4. Screens in This Module

| # | Screen Name | Menu Path | Purpose | Visible To |
|---|-------------|-----------|---------|------------|
| 1 | Administrator Dashboard (`/admin`) | Side menu → **Dashboard** | Organisation-wide summary cards and analytics with filters | Administrator; custom roles holding `dashboard.view.organization` |
| 2 | Manager Dashboard (`/manager`) | Side menu → **Dashboard** | Team summary cards, delayed work, team workload and project progress | Manager; custom roles holding `dashboard.view.team`; Administrator (by direct address) |
| 3 | Employee Dashboard (`/me`) | Side menu → **Dashboard** | The user's own tasks, deadlines, performance, projects and department overview | Every signed-in user (Employee and custom roles land here by default) |

The side menu has a single **Dashboard** item. It always opens the right dashboard for the user: Administrator → `/admin`, Manager → `/manager`; any other role goes to `/admin` if it holds `dashboard.view.organization`, else to `/manager` if it holds `dashboard.view.team`, else to `/me`.

## 6. Permission Summary (Module Level)

| Permission Key | Description | Administrator | Manager | Employee | Custom Role |
|----------------|-------------|:-------------:|:-------:|:--------:|:-----------:|
| `dashboard.view.own` | View my dashboard – personal task summary, deadlines, performance and projects | Always On | Always On | Always On | Always On |
| `dashboard.view.team` | View team dashboard – task statistics and team performance for the people the user manages | Granted | Granted | Denied | Configurable |
| `dashboard.view.organization` | View organization dashboard – task, department, project and employee statistics for the whole organization | Granted | Denied | Denied | Configurable |
| `dashboard.analytics.view` | View charts and reports – status, trend, deadlines, workload and progress | Granted | Granted | Granted | Configurable |
| `dashboard.filters.use` | Use dashboard filters – department, project, employee and period | Granted | Granted | Granted | Configurable |

The three view keys are levels of one selector: Organization includes Team, and Team includes Own. The view keys are described in `02.1-Overview.md`; `dashboard.analytics.view` and `dashboard.filters.use` in `02.2-Analytics.md`.

## 7. Related Modules
- **Monitoring (Task Management)** – every chart click opens the Task List with a drill-down filter; listed tasks open Task Details. The bucket rules are shared with the Task List.
- **Management** – departments, department managers, projects and project allocations decide the department, manager, team and project figures.
- **Settings** – the application timezone (Application Settings) decides "today"; Role Configuration grants the dashboard permissions to roles.
- **Communication** – "due today" and "overdue" use the same day rules as the deadline reminders.
- **Authentication** – after sign-in (and security setup) the user is sent to their dashboard.

## 8. Expected Outcome
Each user opens one screen and immediately sees how much of their work (or their team's, or the organisation's) is pending, in progress, completed and overdue, which deadlines are close, who is overloaded and which projects need attention, and can click through to the exact tasks behind any figure.
